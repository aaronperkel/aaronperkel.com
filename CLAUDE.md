# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Aaron Perkel's personal website (aaronperkel.com) — a Next.js (App Router) + Tailwind CSS v4 + TypeScript site, deployed on Vercel. Every page prerenders static; the single exception is the `/services` inquiry form's POST route (see "Services page" below). It was migrated from a hand-written PHP site in July 2026 (the PHP version is in git history before that point). The old PHP-hosted sub-apps (`checklist/`, `riley21/`, `videos/`) were never part of this repo — they have their own repos in `~/Documents/projects/` and still live on UVM's server.

## Commands

```bash
npm run dev     # dev server
npm run build   # production build (every route prerenders static except /api/inquiry)
npm run lint    # eslint
npm run typecheck     # next typegen + tsc --noEmit
npm run check:resume  # after a build: fails unless resume.pdf is exactly one page
```

CI (`.github/workflows/ci.yml`) runs lint, typecheck, build, and the resume page check on every pull request.

## Architecture

- **`data/*.ts` is the only "CMS"** — `identity.ts`, `projects.ts`, `about.ts`, `resume.ts`, `services.ts`. Edit these to change site copy, resume entries, skills, etc. Some fields in `about.ts` are HTML strings rendered with `dangerouslySetInnerHTML` (a carry-over from the PHP site), so only trusted content belongs there; external links in those strings need `target="_blank" rel="noopener noreferrer"`. `resume.ts` is plain structured data (no HTML) because it feeds both the `/resume` page and the PDF. `services.ts` is mostly plain data, with `proofHtml` as the one trusted-HTML field; it also exports `timelineOptions`/`budgetOptions`, which the form renders **and** the API route validates against, so the allowlist can never drift from the dropdown.
- **`data/identity.ts` is the one source for how the site describes me** — headline, intro, tagline, role, title, meta description, email and profile links. The home page, `/about` metadata, the layout's metadata and Person JSON-LD, the OG image, the resume header, and the CLI output all read from it. Change positioning there, never by editing those consumers. Plain strings only (the CLI prints them verbatim).
- **Projects** — `data/projects.ts` is plain structured data (no HTML): `featured` projects each get a prerendered case study at `/projects/[slug]` (`app/projects/[slug]/page.tsx`), and `otherProjects` are a compact list. `components/ProjectList.tsx` renders both lists and is shared by `/` and `/projects`. Case-study facts come from each project's own repo; leave out anything unverified rather than guess. Old `/?project=<Name>` links (resumes already sent out, indexed URLs, the former modal) are 308-redirected by `proxy.ts` to the matching page, matching on name or former name in `aliases` (case-, accent-, and NBSP-insensitive); other projects anchor into `/projects#<slug>`. Rename a project by adding its old name to `aliases`.
- `app/layout.tsx` — IBM Plex Serif (body) + IBM Plex Mono (nav/labels/metadata) via `next/font`, site-wide metadata (favicons, manifest, apple-web-app), JSON-LD Person schema. Header (which includes Nav) and Footer render around every page inside one narrow document column. No third-party icon/font scripts — glyphs are plain text.
- `app/og.ts` — `openGraph(path)` builds each page's Open Graph block. Next merges metadata shallowly, so a page-level `openGraph` replaces the layout's; every page passes its own path to get a correct `og:url`. New pages should do the same.
- Design tokens (page/ink/muted/rule) are Tailwind `@theme` variables in `app/globals.css`. The palette is neutral (white/near-black, inverted for `prefers-color-scheme: dark`); links are underlined ink rather than colored. Styling is Tailwind utilities in JSX; globals.css has only base element styles.
- `app/robots.ts` / `app/sitemap.ts` generate robots.txt and sitemap.xml; the sitemap includes every featured case study from `data/projects.ts`.
- `next.config.ts` — permanent redirects from the PHP-era URLs (`/index.php`, `/about.php`, `/resume.php`, `/generate_resume_pdf.php`, and `/me.html` → `/me`), redirects sending the UVM-hosted sub-app paths (`/checklist`, `/riley21`, `/videos`) to `aperkel.w3.uvm.edu`, and a rewrite mapping the old `/public/:path*` asset URLs onto `/:path*` (used by the web manifest and any external hotlinks).
- **Resume PDF**: `/resume.pdf` is generated at build time — `app/resume.pdf/route.ts` (`force-static`) renders `components/ResumePdf.tsx` with `@react-pdf/renderer` from the same `data/resume.ts` as the page, so editing the data updates both on the next deploy. This replaced both the PHP/Dompdf generator and the hand-exported `public/resume.pdf` that briefly succeeded it. It must fit on one page: `npm run check:resume` (also in CI) fails otherwise. To eyeball the output locally: `npm run build`, then open `.next/server/app/resume.pdf.body` (it's a plain PDF file).
- **CLI/curl experience** (content ported from a retired Cloudflare Worker; copy now comes from `data/identity.ts` and `data/projects.ts`): `proxy.ts` detects curl/httpie/wget user agents on `/`, `/help`, `/links`, `/projects`, `/json` and rewrites them to `app/cli/[page]/route.ts`, which serves plain text from `data/cli.ts` (ASCII-art landing, links, JSON). `/vcard` (app/vcard/route.ts) serves a downloadable contact card to everyone. Browsers hitting the CLI-only paths get the normal site/404. It only works over HTTPS: `curl https://aaronperkel.com` or `curl -L aaronperkel.com`. A bare `curl aaronperkel.com` gets Vercel's HTTP→HTTPS redirect, which curl doesn't follow by default. That's accepted on purpose (see "Deployment / hosting context").
- **Services page** (`/services`) — the freelance/hire-me page for Aaron Perkel LLC, driven by `data/services.ts`. `components/InquiryForm.tsx` (a client component) POSTs to `app/api/inquiry/route.ts`, the site's **only** dynamic route, which mails the inquiry through Resend's REST API via plain `fetch` (deliberately no SDK dependency) and sends the sender an auto-reply. Requires `RESEND_API_KEY` in the Vercel project — see `.env.example`; without it the route 500s and the form falls back to telling people to email directly. Mail is sent `from` `hello@aaronperkel.com` (a Resend-verified sending identity on the domain, aliased to the real inbox) `to` `me@aaronperkel.com`, with `Reply-To` set to the inquirer so a plain reply reaches them. Spam guards are a honeypot field plus a minimum 3s fill time, both of which return `200` so bots learn nothing; a failed auto-reply is caught and logged rather than failing a delivered inquiry.

## Static odds and ends

- **Contact card** (`/me`) — the luggage-tag page: `app/me/page.tsx` + `components/ContactCard.tsx`, driven by `data/contact.ts`. It is the only place the site shows a phone number and street address, including its own "Add to contacts" download, which `ContactCard` builds client-side from `data/contact.ts`. So `/me` is `noindex` and left out of the sitemap, and that data must not leak into `data/identity.ts`, `data/cli.ts`, `data/resume.ts` (the `/resume` page and PDF), or the layout's Person schema. `/vcard` deliberately carries no phone: it is advertised publicly in the curl output, and `/me` doesn't use it. The public contact page is `/contact` (email, LinkedIn, GitHub, resume). A printed QR code points at the old `/me.html`, which `next.config.ts` permanently redirects to `/me` — keep that redirect.
- `public/img/` — all images, committed to the repo (they were deployed out-of-band in the PHP era).

## Deployment / hosting context

- Vercel deploys from this repo; pushing to `main` updates production once the Vercel project is connected.
- DNS is on Cloudflare, and **every record is DNS-only (grey cloud), including the apex**. Vercel terminates TLS itself and auto-renews its 90-day Let's Encrypt certificate for the apex. Don't turn the Cloudflare proxy back on. Until October 2026 the apex was Proxied, with a Cloudflare Worker in front so a bare `curl aaronperkel.com` (plain HTTP) got the CLI text. That made Vercel report "Invalid Configuration" for the domain, which stopped it renewing the certificate. Once the certificate expired, Cloudflare (SSL mode Full (Strict)) served error 526 for the whole site. The Worker was retired, and the no-scheme curl shortcut was given up rather than repeat that. If the site ever shows a certificate error, first check that the apex is still grey-clouded and that Vercel → Settings → Domains shows it as valid.
- The UVM server (`aperkel.w3.uvm.edu`, "silk") still hosts the sub-apps and `cal.ics`; `minecraft.aaronperkel.com` points at a separate host. Keep those DNS records intact when changing domain settings.
